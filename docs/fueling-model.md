# 静态补给模型与计算器

Issue [#15](https://github.com/The-V-Factor/Kairos/issues/15)。当前模型版本为 `steady-road-v2`。出发前在浏览器本地计算，生成固定累计里程点；不在骑行时重新计算，不需要后端、历史 FIT 或自有手机／手表 App。

## 输入与默认假设

计划统一入口先选择「手动填写／自动生成」，首页没有独立的自动生成栏或路线操作行，已选路线仅作文字摘要；路线选择与更换收进计划面板，手动可不选路线。正式生成读取当前或本次选择的路书、全局档案中的 FTP 和体重，以及所选本次强度。缺少 FTP／体重或有效海拔时明确说明原因，不根据性别、年龄、身高猜值。档案中的另外三项仍保留，但此版不人为将其加入公式。无路书时需要用户选择路书，或主动在计算器设置模拟路线，不能默认为平路。自动流程中选择／移除路线只改暂存配方，保存新计划才写入计划库；没有任何计划时也能打开路线选择。

计算器是独立 `calculator.html` 页面。直接进入时明确标注示例 FTP 250 W、体重 70 kg，可从档案带入；从生成页进入则保留本次参数。所有修改只作用于试算副本，不回写档案或原路书。模拟路线由每段距离、坡度组成，总距离和爬升由分段推导，不把总爬升当成完整地形。

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| 强度 | 70% FTP | 轻松／耐力／较强入口分别为 60%／70%／80%，这是产品预设 |
| 车与装备 | 10 kg | 加上骑手体重得到总质量 |
| 滚阻 Crr | 0.004 | 假定硬质铺装路面 |
| 风阻 CdA | 0.32 m² | 车辆与骑姿的合并假设，不声称由档案精确推导 |
| 空气密度 | 1.20 kg/m³ | 固定无风条件 |
| 传动效率 | 97.5% | 曲柄功率传至车轮的比例 |
| 人体效率 | 22% | 机械做功／代谢消耗，仅作能耗估算假设 |
| 限速 | 45 km/h | 模拟中超过此速度减少踩踏或滑行，不代表道路限速建议 |
| 每支胶 | 用户所选的个人能量胶含量 | 在个人档案→我的能量胶中配置名称与碳水；不以统一品牌或固定克数代替用户选择 |
| 喝水间隔 | 20 分钟 | 仅提醒，不给出水量；0 为关闭 |

常见功率分区参考 [Coggan](https://www.trainingpeaks.com/blog/power-training-levels/)：耐力 56–75%、节奏 76–90%、阈值 91–105%、VO₂max 106–120%。计算器允许试算更高强度，但接近或超过阈值时提示不代表能全程持续；长途也未模拟疲劳衰减。

## 从路书到移动用时

1. 将轨迹累计距离映射到路书总距离；按约 50 m 重采样，最多 10,000 个计算段。
2. 在重采样海拔上使用权重 1／2／3／2／1 的短距离对称窗口，端点保留。缺失、乱序或明显异常海拔不当作平路处理。
3. 根据段长与海拔差算坡角，每段求解无风匀速功率平衡：

```text
P目标 = FTP × 强度
η传动 × P = [mg(sinθ + Crr·cosθ) + ½ρ·CdA·v²] × v
段用时 = 段距离 ÷ v
```

固定功率、正速度区间用 50 次二分求解。若目标功率对应的速度超过限速，采用限速并反算实际所需踩踏功率；所需功率为负时按滑行／刹车处理，踩踏功率记为 0，不产生负能耗。没有模拟惯性、弯道、红灯、停车、风、跟车、路面变化或疲劳，因此输出是情景下的预计移动用时。

4. 计算前将模型总距离统一到现有计划的显示／导出精度，等比调整计算段距离并重算坡角，避免预览和训练终点不同。
5. 累加每段时间形成时间—累计里程表。补给时刻落在某段时，使用该段速度插值，不使用全程均速分配位置。

依据：[Martin 等，1998](https://pubmed.ncbi.nlm.nih.gov/28121252/)；[真实路线的后续验证与海拔处理](https://www.uni-konstanz.de/mmsp/pubsys/publishedFiles/DaBySa09.pdf)。本版是基于该类模型的简化实现，原论文的验证精度不等于本产品的实际 ETA 精度。

## 能耗与补给分开计算

```text
机械做功（J）= Σ(实际踩踏功率 × 分段秒数)
踩踏能耗估算（kcal）= 机械做功 ÷ 人体效率 ÷ 4184
```

此值不包括滑行时的基础代谢、停车等消耗，不是全天总能耗。人体效率无法仅由五项档案确定；个人差异见[功率估算能耗研究](https://pubmed.ncbi.nlm.nih.gov/23470312/)。改变人体效率应改变能耗，不能直接改变胶的数量。

[Maurten Long ride](https://www.maurten.com/education/fuel-guides)及其[官方PDF](https://www.maurten.com/fuelguide/download-pdf/000e1514-081c-409b-8d35-acbd84f5e81c)给出长途总碳水30–60 g/h，明确可以使用胶和饮料组合。Gel 100每支25g碳水；这不是每小时必吃几支的规定。

[AIS](https://www.ausport.gov.au/ais/nutrition/supplements/group_a/sports-foods2/sports-gels) 给出耐力运动 1–2.5 h 的碳水参考范围 30–60 g/h，更长运动可考虑更高摄入，并强调碳水来源和耐受。其建议不是 FTP 到 g/h 的确定公式。

自动选择采用以下**产品默认规则**，用户可以覆盖为 0–90 g/h：

| 预计移动用时 | 默认目标 |
| --- | --- |
| 不足 45 分钟 | 不排吃胶提醒 |
| 45–75 分钟 | 25 g/h，小量补充的产品预设 |
| 超过 75 分钟 | 强度 ≤65% 时30，≤75% 时45，更高时60 g/h；长途不再因时长自动升至60 |

30／45／60是本产品在上述范围内的可调起点，不是Maurten规定的FTP映射公式。

纯胶方案：间隔 = 每支碳水／每小时目标。首支放在半个间隔，随后按完整间隔排点，终点之后不排；这是整支离散提醒的实现选择，不是Maurten要求的固定服用时间。每支含量来自所选个人胶；先不接入食物／饮料碳水的分配或抵扣，也不自动使用咖啡因胶。独立计算器未选产品时仍可按示例45g自由试算，但保存生成计划前必须选择自己的胶。

结果显示胶数、总碳水及计划平均摄入量；整支取整会与目标存在差异，不能将其称为实际完成摄入。出发前进食与个人耐受不由模型推断。喝水独立按间隔安排，不从FTP或体重推断准确水量。

里程按既有一位小数精度取整，同位置的吃胶和喝水合并为一个自定义提醒；多包保留数量。超过现有100个点位容量明确报错，不静默截断。短途可能没有自动补给，仍可保存为空草稿后手动添加。

## 同一模型、独立存档与导航

`fueling-model.mjs` 负责物理、时间映射与补给；`generation.mjs` 负责生成配方、跨页面传递与独立计划。`calculator.mjs` 和 `generator.mjs` 都调用同一入口 `calculateRecipe`，不各写一套公式。

跨页面参数只放 `sessionStorage` 的 `kairos.web.generation.v1`。配方含模型参数、模拟分段和原计划版本，不复制账号令牌。计算器预览回到首页的生成面板；返回设置可继续调整。保存前重新读取计划库，校验原计划版本，创建全新 UUID 与点位 UUID，原计划、导出历史、档案不变。另一标签页修改／删除原计划后拒绝保存过期预览；配额不足或损坏存储不报告保存成功。保存成功后仍使用既有编辑器及 `.workout` 编码器。

### Maurten指南解读与产品规则

官网将Long ride列为Training，30–60g/h针对途中全部来源；Road比赛指南另列60–90g/h。PDF表头的Pre-race／During the race不能单独作为“只适用于比赛”的依据。结合品牌How to fuel对普通饮食的说明，Nothing应理解为未指定额外品牌运动食品，不能理解为空腹出发或不吃饭。

首页三个组合为可选示例，不相加；其中40g饮料＋25g胶为65g，略超文字区间上沿，不应把该图编成严格上限算法。Gel 100 Caf含咖啡因，不能把它当普通Gel 100无区别重复排点。第二页强调组合与训练适应，第三页强调个体化饮水；PDF中的运动后补液描述不能当成骑行中的固定饮水量。

30／45／60g/h对应本产品强度档位属于可调整的产品预设，不能声称来自Maurten的FTP公式。身高体重年龄性别FTP不提供肠胃耐受数据。参考[AIS对运动胶耐受的说明](https://www.ausport.gov.au/ais/nutrition/supplements/group_a/sports-foods2/sports-gels/are-there-any-concerns-or-considerations)，补给目标与实际胃肠耐受需分开。

本次发布收敛到纯胶，不提供食物／饮料碳水输入。用户在个人配置中保存多款胶并在计划中选择；Maurten仅作为长途总目标范围的参考，不预设个人品牌。固定8小时、每支45g时，30／45／60g/h分别生成5／8／11支，总量225／360／495g，计划平均28.125／45／61.875g/h。首支为半间隔，终点时刻不新增提醒；整体取整误差最多半支。另有218km合成爬坡场景检查，用于计算回归，不冒充用户真实路书。

验证：112项Node测试通过，涵盖独立胶数算术、提醒时间、累计里程映射、合并后数量守恒及命名日期传递。浏览器与生产发布结果记录在关联PR。触摸聚焦outline为none，原生Tab后恢复2px轮廓。


## 个人能量胶与快照

个人档案底部「我的能量胶」管理多个名称、每支碳水（5–100g，最多一位小数）。空配置不伪造产品。配置单独保存到 `kairos.web.gels.v1`，不混入身体档案，也不受iGPSPORT导入影响。不可读、未来版本、写入失败均保留原始存储并显示提示。

计划入口与生成面板可选择自己的胶；生成必须明确选定一款。计算器选择个人胶时锁定含量，手动试算模式可自由修改含量。选中胶的含量是模型的权威输入，即使旧配方的数值字段不一致也以选中胶为准。跨页面与重置计算参数保留所选胶及名称日期。

计划与导出历史的可选 `gel` 字段保存ID、名称、每支碳水快照，保持现有计划库版本兼容。个人胶改名、改含量或删除，不修改旧计划、点位或导出历史；界面提供明确的「计划快照」选项，用户可重新选择新版胶。手动计划可不选胶，原有手动记录仍可编辑及导出。

本轮回归：112项Node测试，52项生成／个人胶浏览器检查、27项旧档案检查通过，使用合成资料。个人配置、计划选胶与生成面板在402×700下检查；触摸不显示程序聚焦外框，原生Tab保留2px提示。新版本真实手机验收继续由用户完成。
